# Babysitter — мод для Claude Code, который следит за фоновыми агентами

Видео: **«I Built a Claude Code Mod That Babysits My Agents»**. Срок: эта неделя (1–2 дня на билд, плюс запись).
Билд: Claude Code 2.1.288 (Mods вышли в 2.1.287). Скоуп проверен по типам API этого билда.

---

## 1. Что делает мод (одним абзацем для зрителя)

Запускаешь 3–5 фоновых агентов и уходишь пить кофе. Мод видит каждый шаг каждого агента, замечает, когда агент
застрял, ходит по кругу, сыплет ошибками или жжёт токены, **сам останавливает его, разбирается, что пошло не так,
и перезапускает с исправленной задачей**. Когда все закончили, присылает отчёт: кто что сделал,
сколько это стоило и где были проблемы. Отчёт приходит в терминал, в файл и пушем на телефон.

## 2. На чём это держится (API, проверено по `claude-code.d.ts`)

| Нужно | Чем делаем |
| --- | --- |
| Узнать, что агент стартовал (задача, тип, модель, фон или нет, родитель) | `on('agent.spawn')` → `await next(e)` → получаем `agentId` |
| Видеть каждый шаг агента | `on('tool.call')`: у вызова внутри сабагента есть `e.agentId`; `await next(e)` даёт `isError` и текст результата |
| Узнать, что агент закончил, его ответ, длительность и токены | `on('turn.complete')` с `e.agentId`: `answer`, `durationMs`, `reason`, `usage` |
| Статусы running / completed / failed / killed | `$.agent.list()` раз в N секунд через `$.clock.every` |
| Остановить агента | `$.tool.call` → `TaskStop` |
| Перезапустить с исправленной задачей | `$.agent.spawn({ prompt, description, subagentType, model })` → новый `agentId` |
| Написать работающему агенту (режим nudge) | `$.session.send({ to: { agentId }, text })` или `$.session.append({ agentId, … })` |
| Пуш на телефон | `$.tool.call` → `PushNotification` (запасной вариант: `$.ui.toast` и звук через `$.audio.play`) |
| Сводка отчёта человеческим языком | `$.model.complete({ model: 'haiku', prompt })` |
| Стоимость сессии | `$.session.usage()` → `cost` |
| Живая панель | `$.ui.open` + `ui.render` на `Pane` |
| Строка статуса | `$.ui.status('🍼 3 running · 1 stuck')` |
| Команды | `$.command.register` + `command.run` |
| Пороги и настройки | `userConfig` в `plugin.json`, редактируются в меню конфига |
| Состояние, переживающее hot reload | `$.state` (атомы) плюс контракт `types/index.d.ts`; история отчётов в `$.store` или в файлах |

## 3. Скоуп: MVP (обязательно для видео)

### 3.1 Трекер
- Запись на каждого агента: `id, description, type, model, background, parentId, startedAt, lastActivityAt,
  toolCalls, lastTool, errors, consecutiveErrors, recentCalls[] (хэш tool+input, кольцевой буфер), usage, status,
  answer, incidents[]`.
- Хуки `agent.spawn`, `tool.call` (после `next`), `turn.complete`, поллинг `$.agent.list()` каждые 5 с.
- Агенты основного цикла (без `agentId`) не трекаем, иначе будет шум.

### 3.2 Детекторы (самое ценное для ролика)
| Детектор | Правило по умолчанию | Почему это реально бывает |
| --- | --- | --- |
| **Loop** | один и тот же `tool + input` ≥ 3 раза из последних 8 | агент перезапускает один и тот же упавший тест |
| **Error streak** | ≥ 4 ошибки инструментов подряд | неправильный путь, нет прав, сломанное окружение |
| **Stall** | нет tool-вызовов ≥ 3 мин при `status: running` | агент повис на долгой команде или dev-сервере |
| **Runaway** | агент работает > 15 мин или > 60 tool-вызовов | агент расползся по задаче |
| **Budget** | стоимость сессии выросла на $X с момента старта агентов | дорогая модель гоняет большой контекст |

### 3.3 Вмешательство: Kill & Correct (решено, режим по умолчанию)
Детектор сработал, и няня **сама** останавливает агента, ставит диагноз и перезапускает его с исправленной задачей.
1. **Kill**: `$.tool.call({ tool: 'TaskStop', task_id })`. Агент помечается 🔴 «остановлен няней», в ленте
   инцидентов появляется причина.
2. **Diagnose**: `$.model.complete` (Haiku) получает исходную задачу, детектор и последние ~10 вызовов с ошибками.
   На выходе короткий диагноз («запускал один и тот же тест 3 раза, падение не связано с кодом: тест зависит от
   сети») и инструкция, как обойти проблему.
3. **Correct & respawn**: `$.agent.spawn({ prompt, description: '↻ ' + description, subagentType, model })`.
   `prompt` = исходная задача + блок *«Предыдущая попытка остановлена. Что пошло не так: … Не повторяй: … Сделай
   так: … Если упрёшься снова, остановись и верни частичный результат с объяснением»*. Новый агент связан с
   исходным (`retryOf`), в панели они видны цепочкой.
4. **Лимит**: не больше `maxRetries` (по умолчанию 1) перезапусков на задачу. Если исправленный агент тоже
   сработал на детектор, он останавливается без перезапуска и попадает в отчёт как «⚠️ нужен человек».
5. **Доставка результата**: родитель ждал ответа от исходного агента, а получил «killed». Поэтому ответ
   перезапущенного агента (`turn.complete` по его `agentId`) няня передаёт в основной разговор через
   `$.session.append` (user-row) и упоминает в отчёте. *Проверяем в спайке.*

Режимы в `userConfig`: `correct` (по умолчанию) · `kill` (только остановка) · `nudge` (написать агенту без
остановки) · `warn`. Кнопки в панели: `Kill`, `Kill & Correct`, `Nudge`.

### 3.4 Отчёт
- Триггер: все фоновые агенты, которых мы видели, перешли из running в другой статус. Плюс ручная команда
  `/babysit report`.
- Содержимое: таблица по агентам (задача · статус · время · tool-вызовы · ошибки · токены), список инцидентов и
  вмешательств, итоговая стоимость, короткая сводка от Haiku «что сделано / что требует твоего внимания».
- Куда уходит: файл `.babysitter/reports/<timestamp>.md` через `$.fs`, notice в сессии (видно в кадре), пуш на
  телефон одной строкой (`3/4 done · 1 killed (loop) · $0.84`).

### 3.5 UI
- **Строка статуса** обновляется всегда.
- **Pane `/babysit`**: живой список агентов с индикатором (🟢 работает · 🟡 подозрение · 🔴 вмешались · ✅ · ❌),
  последним инструментом, временем с последней активности, счётчиками и лентой инцидентов. Кнопки на агенте:
  `Nudge` и `Kill`.
- Команды: `/babysit` (панель), `/babysit report`, `/babysit off|on`.

### 3.6 Надёжность
- Хуки лёгкие: в `tool.call` только запись в state и синхронные проверки, тяжёлую работу (отчёт, модель) делает
  таймер.
- Всё состояние держим в `$.state`, чтобы hot reload во время съёмки ничего не терял.
- Мод не трогает собственные `$.model.complete` и не реагирует на свои же вмешательства (`next.origin`).
- Тесты `claude plugin test`: loop → nudge → kill; error streak; отчёт при завершении всех агентов.
  Плюс `claude plugin validate` и `tsc`.

## 4. Вне MVP (делаем, если останется время)
- **Guard**: deny опасных Bash-команд у фоновых агентов (`rm -rf`, `git push --force`, запись вне cwd через
  `realPath`). Хорошо смотрится в кадре, но это отдельная тема.
- Свой сабагент-тип `babysitter:reviewer`, который после завершения проверяет diff агента.
- Звук при инциденте.
- Мониторинг агентов **других** сессий или процессов. Не делаем: API видит только текущую сессию.
- Slack, веб-дашборд. Не делаем.

## 5. Демо-прогон для видео («реальный прогон»)
Нужен **воспроизводимый демо-репозиторий с ловушками**, чтобы каждый детектор гарантированно сработал в кадре:

| Агент | Задача | Что произойдёт |
| --- | --- | --- |
| A | «Добавь тесты для `utils/date.ts`» | честно справляется ✅ |
| B | «Почини `test/flaky.test.ts`» (тест зависит от сети или времени, правкой кода его не починить) | **Loop**, kill, диагноз и перезапуск: «замокай сеть», после чего ↻B проходит ✅ (главный кадр) |
| C | «Подними dev-сервер и проверь `/health`» (порт занят, сервер никогда не отвечает) | **Stall**, kill и перезапуск; ↻C снова упирается, остановлен, «⚠️ нужен человек» (показываем лимит) |
| D | «Отрефактори модуль X» | долгий, но нормальный; показывает, что ложных срабатываний нет ✅ |

Финал: агенты закончили, в терминале появился отчёт, на телефон пришёл пуш. Это кадр для превью и концовки.
Для съёмки ставим пороги ниже (stall 60 с, loop 3), чтобы прогон уложился в 5–8 минут.

## 8. Риски
- **API ранний и меняется между релизами.** Пинимся на 2.1.288 и в README пишем минимальную версию.
- **Pane без явного действия открывается только при ширине от 144 колонок.** Поэтому открываем её командой
  `/babysit`, а запись идёт на широком терминале.
- **`PushNotification` может требовать Remote Control.** Запасной вариант: тост и звук; проверяем в спайке.
- **Ложные срабатывания loop на законных повторах** (например, `Read` одного файла после правки). В хэш входит
  input, а `Read` / `Grep` получают порог выше.
- **Перезапуск может повторить ту же ошибку.** Поэтому лимит `maxRetries`, диагноз от Haiku с конкретным «не делай X», а повторный сбой означает «нужен человек».
- **Агенты Workflow и форки движка имеют id, которых нет в `$.agent.list()`.** Их игнорируем.

### Прогон 2: корректирует ли мод сабагентов (3 агента, одна и та же зацикленная задача)
| Агент | Вмешательство | Итог |
| --- | --- | --- |
| A | `$.session.append({ agentId, … })`: исправление пишется в разговор агента | ✅ **исправился сам**: после 4-го падения перестал повторять, выполнил исправленную команду и сдал отчёт, процитировав сообщение няни. Классификатор не участвует |
| B | `$.session.send({ to: { agentId } })` | ❌ в auto mode классификатор дважды заблокировал `SendMessage`. Агент дальше крутил цикл (7+ повторов), остановлен через TaskStop |
| C | `TaskStop`, затем `$.agent.spawn` с исправленной задачей | ✅ остановка мгновенная (`turn.complete reason: aborted`); ❌ перезапуск в auto mode дважды заблокирован классификатором |

**Вывод: корректировка работает.** Основной механизм — `append` прямо в разговор агента. Он проверен, надёжен и не
требует прав.

### Пересмотренный Kill & Correct
1. Детектор сработал → **Correct in place**: `append` с диагнозом и инструкцией (как у агента A).
2. Тот же детектор сработал снова после исправления → **Kill** (`TaskStop`).
3. **Respawn** с исправленной задачей (`$.agent.spawn`) работает, только если разрешено: allow-правило на `Agent`
   в settings или режим прав не auto. Если запрещено, няня не обходит запрет: показывает в панели готовую
   исправленную задачу и кнопку `Respawn` (нажатие человека — легитимное согласие), а в отчёте пишет «⚠️ нужен
   человек».
4. `session.send` не используем: `append` делает то же самое без классификатора.
